1. Executive Summary

The existing repository is a pnpm-workspace monorepo (VERIFIED — README) containing a React 19 + Vite 7 + TypeScript single-page frontend, an Express + Node.js backend with a REST API and EJS fallback views, PostgreSQL in production / JSON-file storage in development, and a PM2 + Nginx production deployment. It is the marketing site for WirfonCloud, a Rwanda/Cameroon-founded (per About page copy) cloud-computing training and consultancy brand, with pages: Home, Academy, Consultancy, Blog, Gallery, About, FAQ (VERIFIED — README + screenshots, exact match).

Structurally, this is a generic "brochure site engine": a marketing header/nav/footer shell, a card-grid content system (courses, services, blog posts, testimonials, FAQ accordion, gallery-with-lightbox), a contact/newsletter form, an admin CMS behind /admin, and a REST API + Postgres/JSON persistence layer. None of that is domain-specific to cloud training — the same shell can plausibly hold "Research Areas," "People," "Publications," "Courses," and "Initiatives" for P3 Health Lab. The brand-specific layer (WirfonCloud name, blue/black color scheme, cloud logo, AWS partner content, testimonials, blog posts, gallery photos, contact details) is content and assets sitting on top of that shell and must be fully replaced.

The biggest open risk is that I cannot confirm from source how tightly the content is coupled to components — i.e., whether page content lives in typed data files/JSON (easy to swap) or is hardcoded inline in JSX (requires refactoring).
