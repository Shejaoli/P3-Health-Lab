MANDATORY PHOTO-TO-PERSON MATCHING

THIS IS REQUIRED — DO NOT SKIP IT.

Before associating any image with a person, inspect the filename of every supplied image.

The filename is the primary source of truth for identifying who the image belongs to.

For example:

Dr-Egide-Kalisa.png

Dr. Md Pervez Kabir.jpg

Allison-Pert.webp

Augustine-Omodieke.png


The agent must:

1. Read the filename.


2. Extract the person's name from the filename.


3. Normalize harmless differences such as:

., -, _

capitalization

spaces

common filename formatting



4. Match that name against the existing 37 People records.


5. Associate the image only when the filename can be confidently matched to an existing person.



IMPORTANT — DO NOT GUESS

Do not identify a person based only on:

appearance

facial similarity

assumed identity

image ordering

folder ordering

upload ordering

metadata that does not clearly identify the person


If the filename says a name that exists on the website, associate it with that person.

If the filename contains a name that does not exist in the current People directory, ignore/drop that image. Do not create a new People record just because an image exists.

For example:

John-Smith.png

If John Smith is not one of the existing People records, do not add John Smith and do not attach the image to somebody else.

MULTIPLE IMAGES

If multiple images resolve to the same person:

do not create duplicate People records;

choose the appropriate existing image according to the existing upload workflow;

report the duplicate filename(s) rather than silently assigning them to another person.


MISSING IMAGES

If a person's name exists on the website but there is currently no matching image:

leave that person's profile without a portrait;

do not invent/generate one;

do not use another person's image;

do not block the rest of the implementation.


The system must allow those missing portraits to be uploaded later through /upload.
